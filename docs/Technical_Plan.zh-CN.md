# CS290U 2.2 技术方案｜用 LoRA 将晴天街景迁移为雨天

**组会讨论稿 · 2026 年 11 月 28 日**

> 给定一张白天晴天的驾驶视角照片，让路面变湿、出现合理的反光和雨天光照，同时让道路、建筑、车道线和车辆留在原来的位置。我们先测雨天 LoRA 能否提高雨效，再测 SMS 能否在相近雨效下进一步减少布局漂移。

主线暂按 **BDD100K 白天晴 → 白天雨、Stable Diffusion 1.5、单张 A40** 设计。以下模型设置、样本规模和超参数是首轮方案。正在运行的小测试暂未有可核验的本组出图、评分和耗时，本稿的预期均为待检验假设。 任务依据 CS290U 结课项目说明第 2.2 节。

**与仓库小测的对应。** [当前小测](../README.md)默认用 160 张城市白天雨图训练、20 张晴图做开发对照，推理尺寸为 768×432。小测的两条流程都从晴图出发。本方案中的 B3 从 B2 输出初始化，并计划增加 B0、B1、频谱消融和独立盲测，属于后续实验。

## 1. 研究问题

| 研究问题 | 用什么实验回答 |
| --- | --- |
| **RQ1**　同样给定雨天提示词和原图边缘，自训雨天 LoRA 能否提高雨天达成率，同时保住布局？ | B1 对 B2，仅改变是否加载雨天 LoRA |
| **RQ2**　给定同一个雨天 LoRA 和同一张初始结果，SMS 能否减少车道、车辆和建筑的布局漂移，同时维持类似的雨天效果？ | B2 对 B3，再比较不同图生图强度下的雨效与布局取舍 |
| **RQ3**　若 SMS 有收益，渐进频谱正则是否贡献了结构保持？收益需要多少额外时间？ | B3 对频谱项关闭版，记录结构、雨效和逐图耗时 |

允许改变天空、色温、路面光泽、反射和雨纹。布局保持重点看道路边界与车道走向、主要车辆的数量与位置和建筑轮廓。局部低对比可由雨效造成。新增一辆车、原车消失、车道拐向和建筑轮廓拉伸属于布局错误。

## 2. 数据与 LoRA 训练

从 BDD100K 按 `timeofday=daytime` 和 `weather=clear/rainy` 筛选，城市街道与高速作为两个场景切片。使用真实雨天图学习目标域外观，用留出的晴天图测试同场景编辑。数据集提供天气、时段和场景字段。[BDD100K 标注格式](https://github.com/bdd100k/bdd100k/blob/master/doc/source/format.rst)

| 数据 | 首轮规模 | 用法 |
| --- | --- | --- |
| 白天雨天训练图 | 目标 600 张，以实际筛选数量为准 | 训练一份雨天 LoRA，按城市街道和高速分层抽样 |
| 晴天开发图 | 20 张，正在运行的试验图归入此集合 | 看接入是否正常，选择推理强度、LoRA 权重和 SMS 参数 |
| 晴天盲测图 | 48 张，城市街道与高速各 24 张 | 同一批原图运行所有主对照；提前固定 24 张的人工复核子集 |
| 白天雨天参考图 | 留出 20 张，与训练图互斥 | 校准人评对真实雨天的判断，展示外观参照 |

按官方划分和图像／片段 ID 冻结清单。开发图与盲测图互斥，多帧同片段时归入同一集合。筛掉明显错标、重复帧和严重遮挡。晴图和雨图是未配对的，因此不存在同一条街、同一视角的雨天像素真值。

**训练方式。** 用真实白天雨图和简短描述训练 SD 1.5 的文本条件 LoRA。描述同时写场景类型和天气，例如 `daytime dashcam photo, city street, rainy weather, wet road`，并随场景修改。去噪损失作用于雨天训练图的加噪潜变量。只训练 UNet 注意力层 `to_q/to_k/to_v/to_out.0` 的 LoRA 参数，VAE、文本编码器、UNet 基座冻结。Canny ControlNet 作为冻结的推理条件使用。[SD 1.5 模型卡](https://huggingface.co/stable-diffusion-v1-5/stable-diffusion-v1-5) · [Diffusers LoRA 训练](https://huggingface.co/docs/diffusers/training/lora)

**起跑配置。** 等比例缩放到 640×360，训练和推理保持同一裁切规则。LoRA 先试 rank 8、alpha 8、学习率 `1e-4`、有效 batch 4，约 1,000 个优化步，在 400／700／1,000 步留点。短跑先核对显存、梯度和权重加载，按开发集选择一个检查点供全部对照复用。

## 3. Baseline 与 SMS 怎么接

| 组别 | 方法 | 这组的作用 |
| --- | --- | --- |
| B0 | SD 1.5 Img2Img + 雨天提示词 | 测图生图提示词本身能做到什么 |
| B1 | B0 + 冻结的 Canny ControlNet，边缘图来自原图 | 测空间条件对道路、建筑、车道和车辆的作用 |
| **B2 主基线** | B1 + 同一份自训雨天 LoRA | 测雨天域适配。也是 SMS 要比较的基线 |
| **B3 候选方法** | 以 B2 结果初始化，使用同一雨天 LoRA 做逐图 SMS 优化；以原始晴图作为结构参照 | 测 SMS 能否纠正 B2 的结构漂移或提高雨效，同时保住另一项 |
| B3 去频谱项 | B3 的频谱正则权重设为 0，初始化、其他梯度项和迭代预算一致 | 测频谱项对雨效和布局各有什么影响 |

**B2 的推理设置。** 用原图同时做 Img2Img 输入和 Canny 来源，提示词固定为白天驾驶照片、自然雨天、湿路和适量反光。初始设置用 DDIM 30 步、CFG 6、Img2Img strength 0.60、Canny 权重 0.9、LoRA 权重 0.8。先在开发集确认出图，随后冻结主配置和种子。B0–B2 共享输入、提示词、采样器与随机数设置，启用的模块按表区分。[ControlNet 论文](https://arxiv.org/abs/2302.05543) · [SD 1.5 Canny 权重](https://huggingface.co/lllyasviel/control_v11p_sd15_canny)

**SMS 实现。** SMS 原论文用带目标 LoRA 的扩散模型提供风格匹配方向，用渐进频谱正则约束与源图的潜变量差异，并用语义相关梯度调节编辑区域。我们把目标域换成白天雨天，拟从 B2 出图开始做逐图优化，频谱参照仍取原图。冻结雨天 LoRA，逐图估计当前生成分布所用的辅助适配器单独初始化，避免跨测试图继承状态。B2 和 B3 一起保存，零轮优化应直接返回 B2。StyleSSP 改的是扩散采样起点，SMS 这里研究的是优化目标，正式方法名按实际启用的模块填写。[SMS 论文](https://openaccess.thecvf.com/content/ICCV2025/html/Jiang_Balanced_Image_Stylization_with_Style_Matching_Score_ICCV_2025_paper.html) · [SMS 官方代码](https://github.com/showlab/SMS) · [StyleSSP 论文](https://openaccess.thecvf.com/content/CVPR2025/html/Xu_StyleSSP_Sampling_StartPoint_Enhancement_for_Training-free_Diffusion-based_Method_for_Style_CVPR_2025_paper.html)

**接入校验。** 官方 SMS 示例直接处理图像，加载器按 Civitai 风格的键名读取权重。先确认自训 Diffusers LoRA 在两条路径都实际生效，并锁同一 SD 1.5 快照、相同有效 LoRA 权重。若已运行的小测试只实现了其中一项，按实际算子命名并给出对应消融。若小测试走独立 SMS 路径，就把它记为独立方法对照，另做同一 B2 初始图上的开关实验来检验增量。[官方加载实现](https://github.com/showlab/SMS/blob/main/sms.py)

## 4. 对照协议与评价指标

**正式主表**在冻结的 48 张晴图上跑 B0–B3。各组共用 `source_id` 和预先固定的种子，不按图挑结果。先在开发集扫描 B2 的 strength `0.45 / 0.60 / 0.75`，SMS 则扫描频谱权重与优化轮数。在测试集保留 B2 三档，画出雨天达成率与布局保持的关系。重点看 B3 在相近雨天达成率下是否还能提高布局保持，避免把弱雨效带来的结构优势归给 SMS。B3 的频谱消融优先跑预先固定的 24 张子集，与这些图上对应的 B3 配对。逐图优化成本若明显增加，再加一组有同等时间预算的 B2 多步采样，并公开两者实际耗时。

| 指标 | 具体计算 | 用来判断什么 |
| --- | --- | --- |
| **雨天达成率 ↑** | 24 张盲评子集。独立看输出，按 `0 晴 / 1 仅阴天或雨迹不明确 / 2 可信的白天雨天 / 3 雨更明显且自然` 评分。`≥2` 且保持白天、无严重天气伪影记为通过 | LoRA 是否带来可信雨效，SMS 是否把雨效削弱。真实雨图作评分校准 |
| **布局通过率 ↑** | 同一子集，显示原图和无方法名的输出。道路与车道走向、主要车辆数量与位置、建筑轮廓三项均无明显结构变化记为通过。标记具体失败类型 | 直接验证课程的布局约束，覆盖小车辆消失等全局分数容易漏掉的错误 |
| **联合通过率 ↑** | 同一输出的雨天与布局均通过的比例，由两项的逐图结果计算 | 衡量实际完成“晴转雨且保布局”的比例 |
| **结构 mIoU ↑** | 全部 48 张，用同一冻结 SegFormer 分别分割原图和输出。逐图计算道路、建筑、车三个类别在对应像素上的 IoU，再对有并集的类别平均，同时报告分项 | 自动结构代理。模型在雨天可能漏分割，图上高分或低分用盲评与局部检查解释 |
| **耗时与显存** | 单卡热身后按端到端秒／张报中位数和 P90，包含预处理和 SMS 循环，另报峰值显存 | 判断逐图优化的额外计算是否值得 |

每张人工样本使用相同评审准则，隐藏方法和顺序，三份独立评分取多数。主表给出分子／分母。按源图对 B2、B3 的差值做配对 bootstrap 区间，并报告城市街道、高速和典型失败。全图 PSNR、SSIM 容易把所需的光照改变也当成误差，可省略。结构评分不直接复用 Canny 条件图。[SegFormer Cityscapes 权重](https://huggingface.co/nvidia/segformer-b2-finetuned-cityscapes-1024-1024)

## 5. 预期效果与组会展示

| 要展示的内容 | 建议版式 | 讲解重点 |
| --- | --- | --- |
| 第一张同图对照 | `晴天原图` · `B1 提示词 + Canny` · `B2 加雨天 LoRA` · `B3 加 SMS` | 先看路面从干到湿、反光与光照是否像雨天。再对照同一条车道线、同一辆车和同一栋建筑 |
| 第二张困难场景 | 用另一场景复用上面四栏，在同一坐标裁出车道、远处车辆或建筑边缘 | 展示有反光、细线或密集车辆时的失败，解释为什么需要布局指标 |
| 主结果页 | 主表放雨天、布局和联合通过率，配一幅横轴雨天达成率、纵轴布局通过率的图 | 对比两组在相近雨效时的布局分，同页标出耗时 |

**可验证的预期。** B1 的边缘约束有望减少 B0 的几何漂移。B2 的主要收益应出现在湿路、反射和雨天光照。B3 的预期是在保留这些信号时减少错车、变形车道或建筑轮廓漂移。典型的反例是频谱约束过强，把湿路或雨天光照一起拉回晴天。如果 B3 只通过弱化雨效提高布局分，就报告这项取舍。如果 B3 同时改善联合通过率并在相近雨效下保持更多结构，再把它作为项目的主要方法结果。

**当前图证据。** 等本组试验回传后，优先填两组同图对照和一个失败样例。每组标上数据 ID、LoRA 检查点、实际 SMS 开关与用时。试验图用于讨论可行性，正式对照用冻结测试清单产出。

## 6. 单卡运行顺序

排卡前先固定数据清单、检查点和配置，确认离线权重可读。一次单 A40 作业先做 30–50 步训练短跑，再拿同一张源图跑 B1、B2 和 SMS，检查 CUDA、尺寸、LoRA 生效及输出可读。随后按 LoRA 训练／恢复、开发集选参、锁定配置、盲测主表、消融的顺序运行，中间按 `source_id × 方法 × seed` 落盘并支持续跑。

GPU 预算以实测秒／训练步及秒／图算，加上预处理与保存。每组先保存一批结果和日志，资源不足时优先完成 B1、B2、B3 的同图对照，再扩展消融。完整实验预先记录图像清单、模型与 LoRA 哈希、代码版本和实际运行时间。
